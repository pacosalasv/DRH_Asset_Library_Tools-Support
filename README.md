## Read this first

Planned. No download, no date. This repository is where the idea collects evidence before it collects code.

## The idea

Tools for the maintenance side of asset libraries: metadata that stays consistent, assets that are findable months later, and a way to see what a library contains without opening it one asset at a time.

Asset libraries rot in a specific way. The names drift, the tags stop matching, and the good asset becomes the one nobody can find. Fixing that is a data problem more than a modeling one.

## What's decided and what isn't

Settled: it would sit on top of Blender's asset system rather than replace it with a new library format.

Open: whether the useful part is metadata cleanup, browsing and search, or catalog structure. Those pull toward different tools.

## Where the need might already be covered

If the question is what a file references rather than how a library is organized, [Scene Material Inventory](https://github.com/pacosalasv/DRH_Scene_Material_Inventory-Support) audits the open scene today.

[Open an issue](https://github.com/pacosalasv/DRH_Asset_Library_Tools-Support/issues) if you maintain a real library and the maintenance is the thing that costs you. How you organize it is more useful to me than a feature request.
